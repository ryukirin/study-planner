# 空闲时间格式（profile.json）

```json
{
  "version": 1,
  "buffer_minutes": 5,
  "weekly": {
    "mon": [
      {"start": "07:40", "end": "08:20", "tag": "commute", "label": "上班通勤"},
      {"start": "20:30", "end": "22:30", "tag": "focus", "label": "晚上"}
    ],
    "tue": [],
    "sat": [{"start": "09:30", "end": "11:30", "tag": "focus", "label": "上午"}],
    "sun": [{"start": "15:00", "end": "16:00", "tag": "light", "label": "下午"}]
  },
  "holidays": "jp",
  "holiday": [{"start": "10:00", "end": "12:00", "tag": "focus", "label": "上午"}],
  "exceptions": [
    {"date": "2026-12-31", "windows": [], "note": "跨年休息"}
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `buffer_minutes` | 同一时间段里两个任务之间留的分钟数，0 到 60 |
| `weekly` | 键为 `mon` 到 `sun`。没写的星期视为没有空闲时间 |
| `start`、`end` | `HH:MM`，结束可以写 `24:00`。同一天的时间段不能重叠 |
| `tag` | 时间段类型，任务的 `slot` 按它匹配 |
| `label` | 界面上显示的名称 |
| `holidays` | `"jp"` 表示按日本祝日排程，`"none"` 或不写表示不处理祝日 |
| `holiday` | 周一至周五的祝日使用的时间段，格式同 `weekly` 里的一天。不写时用周六的时间段，空数组表示祝日全天没空 |
| `exceptions` | 某天和平时不同时使用。`windows` 为空数组表示全天没空 |

日本祝日由 App 按祝日法自动计算，包括振替休日和国民の休日，覆盖 2020 到 2099 年，不需要逐年写成 `exceptions`。用户在日本工作时，问清祝日是否休息，休息就写 `"holidays": "jp"`，祝日和周六安排不同时再写 `holiday`。

常用 tag：

| tag | 用途 |
| --- | --- |
| `focus` | 能坐下来专心学习的整块时间 |
| `commute` | 通勤，只适合听音频或背单词 |
| `light` | 睡前、午休这类零碎时间，适合复习 |

也可以自定义 tag，例如 `gym`。计划任务的 `slot` 写了 profile 里不存在的 tag 时，这些任务都排不进去，`check` 会给出警告。

## 排程规则

每天先取当天的时间段，优先级为 例外日期 > 祝日 > 星期模板。祝日时间段只用于周一至周五的祝日，周六、周日的祝日仍按当天的星期模板。`planner_cli check` 的空闲时间部分显示祝日是否开启和近期祝日，时间表预览在祝日的日期后标注祝日名称。

取得时间段后，把所有计划当天的任务按 `priority` 从小到大、同一计划内按模板顺序，依次放进第一个 tag 匹配且剩余时间够用的时间段。放不下的任务在 App 里显示为“未排入”。

用户也可以在 App 的“空闲时间”页直接修改，保存后立即生效。
